# Retention / cleanup + policy-driven blob GC — Design & Implementation Plan

**Date:** 2026-05-29
**Slice:** §12.1 of the `envisia-forge` design (builds on the approved Slice 1 spec
`docs/superpowers/specs/2026-05-29-envisia-forge-nuget-design.md`).
**Status:** Draft plan.

## Goal

Add per-repository retention policies (keep-last-N, keep-for-X-days,
keep-N-most-recently-downloaded, proxy evict-not-pulled-in-X-days) evaluated by a
cluster-coordinated background worker that unlists/deletes components and drives
blob GC **exclusively** through the existing Slice 1 transactional outbox.

## Architecture

A new `retention` module in `core` defines a declarative policy model (stored as
`retention_policy jsonb` on `repository`) and a pure evaluator that, given a
repository's components/assets and a policy, computes a deletion/unlist set. A
background `RetentionWorker` (running on every instance, like the Slice 1 outbox
worker) claims one repository at a time via Postgres `SELECT … FOR UPDATE SKIP
LOCKED` over a new `retention_run` ledger so evaluation work is never duplicated
across instances; it applies decisions in small transactions that decrement
`blob.ref_count` and enqueue `blob_outbox` deletes — i.e. it reuses the §4 outbox
+ orphan reconciler instead of adding a parallel S3-deletion path. Download
tracking (`asset.last_downloaded_at`, `proxy_cached_version.last_downloaded_at`)
is added to feed download-sensitive policies, written best-effort like Slice 1's
`token.last_used_at`. An admin REST surface configures policies and exposes a
**dry-run preview**; every applied deletion is recorded in a `retention_audit`
table.

## Dependencies (Slice 1 must exist)

- **`storage` crate** — the CAS refcount semantics and the **transactional
  outbox** (`blob_outbox`, `delete_object` op, outbox worker with revival
  re-check) and the **orphan reconciler**. This slice produces outbox rows; it
  never deletes S3 objects directly.
- **`db` crate** — sqlx pool, migrations runner, data-access layer; advisory-lock
  and `FOR UPDATE SKIP LOCKED` helpers used by the Slice 1 outbox worker.
- **`core` crate** — domain model (`Repository`, `Component`, `Asset`), the
  `delete_component` / asset-deletion operation that already decrements
  `ref_count` and enqueues the outbox row in one transaction, and the **authz
  seam** (admin-only mutation, `is_admin`).
- **`cache` crate** — used to invalidate repository config (and registration /
  flat-container / search documents) for a repo after a retention run mutates it,
  via the L1+optional-L2 invalidation backplane.
- **`server` crate** — axum app, principal middleware, admin REST API, background
  worker wiring (the Slice 1 outbox/reconciler/proxy-refresh workers are started
  here; the retention worker joins them).
- **Tables (Slice 1):** `repository`, `component`, `asset`, `blob`,
  `blob_outbox`, `proxy_cached_version`.

> **Assumption flags (Slice-1 internals referenced by spec name, not yet built):**
> (a) `core` exposes an asset/component delete that decrements `ref_count` and
> enqueues `blob_outbox` in one tx — referenced as `core::delete_component` /
> the redeploy refcount logic in §4/§6 of the spec. This slice calls that path;
> if its signature differs, only the call sites in `retention::apply` change.
> (b) A `db` helper for `SELECT … FOR UPDATE SKIP LOCKED` and advisory locks
> exists (the outbox worker needs it). (c) `cache` exposes a keyed `invalidate`.

## Tech-stack additions

None beyond Slice 1. Reuses tokio (worker), sqlx (jsonb + queries), serde
(policy (de)serialization), the existing config crate for worker tuning. No new
external service. Redis remains optional.

## 1. Scope

### In scope

- `retention_policy jsonb` on `repository` (nullable ⇒ no retention).
- Policy model with criteria parity to Nexus cleanup policies and Artifactory
  retention (survey below).
- Download tracking columns: `asset.last_downloaded_at`,
  `proxy_cached_version.last_downloaded_at`, plus a derived
  `component.last_downloaded_at` (max over its assets) for keep-N-most-downloaded.
- Pure, unit-testable evaluator producing an ordered decision set
  (`Unlist` | `HardDelete`) per component/proxy-cached-version.
- Cluster-coordinated `RetentionWorker` (every instance; Postgres-coordinated;
  no in-memory-only state).
- Applying decisions through the **Slice 1 outbox** (decrement `ref_count`,
  enqueue `blob_outbox`) — never a direct S3 delete.
- Admin REST: get/set policy, trigger run, **dry-run preview**, list audit.
- `retention_audit` table; `retention_run` coordination ledger.
- Cache invalidation after a run.

### Explicitly out of scope

- Direct S3 object deletion (delegated to the Slice 1 outbox worker).
- Orphan reconciliation (Slice 1 backstop, unchanged).
- Per-path / per-name regex selectors beyond a simple optional `package_name`
  glob/prefix (full content-selector RBAC is §12.4) — flagged as an open
  question, not built now.
- "Archive to cold storage" tier (Artifactory Smart Archiving) — forge has one
  storage tier; we delete, not archive.
- Cron expression scheduling UI; we use a fixed evaluation interval +
  per-repo `min_run_interval` + manual trigger. (Cron-style scheduling is an
  open question.)
- Frontend (policy editor UI is part of §12.6).

## 2. Parity survey (Nexus + Artifactory) → policy model

**Nexus Repository cleanup policies** support, ANDed together:
`criteriaLastBlobUpdated` (component age in days), `criteriaLastDownloaded` (days
since last download), `criteriaReleaseType` (RELEASES / PRERELEASES), optional
name/namespace/path regex, and `retain` = keep last N versions (newest kept;
PostgreSQL deployments, release repos). Policies attach to repositories; deletes
are soft-then-hard via the blob store's compaction.

**Artifactory retention / archive policies** combine *keep N versions* with *max
age in days*; archive-by-created-age and archive-by-downloaded-age; version-based
keep-N for Docker/OCI/Helm. The policy is "always a combination" of count + days.

**forge policy model (reflects the above):** a repository's `retention_policy` is
a list of **rules**; a component is deleted/unlisted iff it matches a rule. Within
a rule, criteria are **ANDed** (Nexus semantics). Across rules, a component is
acted on if **any** rule selects it (union), but `keep_last_n` /
`keep_n_most_downloaded` **protection always wins** (a protected version is never
deleted regardless of age rules — see algorithm §3.6). Each rule:

```jsonc
// repository.retention_policy (jsonb), shape v1
{
  "version": 1,
  "enabled": true,
  "dry_run_only": false,           // safety: evaluate + audit but never apply
  "min_run_interval_seconds": 3600,
  "rules": [
    {
      "id": "keep-recent-releases",
      "action": "hard_delete",      // "unlist" | "hard_delete"
      "release_type": "any",        // "any" | "releases" | "prereleases"
      "package_name_prefix": null,  // optional case-insensitive id prefix filter
      "criteria": {
        "keep_last_n": 10,                 // protect newest N (by semver) — Nexus retain / Artifactory keep-N
        "keep_n_most_downloaded": null,    // protect N most-recently-downloaded
        "older_than_days": 90,             // component age since created_at (Nexus criteriaLastBlobUpdated)
        "not_downloaded_for_days": 30      // since last_downloaded_at (Nexus criteriaLastDownloaded)
      }
    },
    {
      "id": "proxy-evict-cold",
      "action": "hard_delete",
      "scope": "proxy_cached",      // proxy-only rule operating on proxy_cached_version
      "criteria": { "not_pulled_for_days": 30 }   // proxy "evict cached not pulled in X days"
    }
  ]
}
```

Notes:
- `keep_last_n` and `keep_n_most_downloaded` are **protections** evaluated per
  `(repository, package_name)` group, not deletion triggers; the age/download
  criteria are the triggers, exactly mirroring Nexus (`retain` + AND criteria).
- `release_type` maps to NuGet semver: a version with a prerelease label is a
  prerelease, otherwise a release.
- `scope: proxy_cached` rules target `proxy_cached_version` (cached upstream
  metadata + downloaded bytes) and only make sense on `kind = 'proxy'` repos;
  validated at config time.
- `dry_run_only` lets an operator stage a policy and inspect audit output before
  arming it.

## 3. Design

### 3.1 Data-model changes (consistent with Slice 1 naming)

New migrations under `migrations/` (sqlx, sequential after Slice 1):

```sql
-- repository: add the policy column (nullable ⇒ no retention)
ALTER TABLE repository
  ADD COLUMN retention_policy jsonb NULL,
  ADD COLUMN retention_last_run_at timestamptz NULL;   -- advisory only; ledger is authoritative

-- download tracking (best-effort writes, like token.last_used_at)
ALTER TABLE asset
  ADD COLUMN last_downloaded_at timestamptz NULL,
  ADD COLUMN download_count bigint NOT NULL DEFAULT 0;

ALTER TABLE component
  ADD COLUMN last_downloaded_at timestamptz NULL;       -- denormalized max over assets; for keep_n_most_downloaded

ALTER TABLE proxy_cached_version
  ADD COLUMN last_downloaded_at timestamptz NULL;       -- proxy "not pulled in X days"

-- per-repo coordination ledger (authoritative scheduling state; no in-memory-only state)
CREATE TABLE retention_run (
  repository_id   bigint PRIMARY KEY REFERENCES repository(id) ON DELETE CASCADE,
  state           text   NOT NULL DEFAULT 'idle',   -- 'idle' | 'running'
  next_run_at     timestamptz NOT NULL DEFAULT now(),
  started_at      timestamptz NULL,
  finished_at     timestamptz NULL,
  locked_until    timestamptz NULL,                 -- lease, mirrors blob_outbox.locked_until
  last_error      text NULL,
  last_run_summary jsonb NULL                       -- counts: evaluated/unlisted/deleted/blobs_enqueued
);

-- append-only audit of every decision actually applied (and dry-run previews if persisted)
CREATE TABLE retention_audit (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  repository_id bigint NOT NULL REFERENCES repository(id) ON DELETE CASCADE,
  run_id        uuid   NOT NULL,                    -- groups one evaluation pass
  rule_id       text   NOT NULL,
  action        text   NOT NULL,                    -- 'unlist' | 'hard_delete'
  target_kind   text   NOT NULL,                    -- 'component' | 'proxy_cached_version'
  package_name  text   NOT NULL,
  version       text   NOT NULL,
  component_id  bigint NULL,                         -- nulled after hard delete (FK ON DELETE SET NULL)
  blob_sha256   text   NULL,                         -- the .nupkg blob touched
  ref_count_after bigint NULL,                       -- observed after decrement
  blob_delete_enqueued bool NOT NULL DEFAULT false,
  dry_run       bool   NOT NULL DEFAULT false,
  reason        jsonb  NOT NULL,                     -- which criteria matched, protections that applied
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX retention_audit_repo_run_idx ON retention_audit (repository_id, run_id);
CREATE INDEX retention_audit_created_idx  ON retention_audit (created_at);
```

`component.last_downloaded_at` is maintained on the download path (§3.7); the
evaluator reads it directly so it does not have to aggregate assets at evaluation
time. `retention_run` rows are created lazily (upsert) the first time a repo with
a policy is seen.

### 3.2 New / changed crates & modules

All under the Slice 1 layout — **no new crate**:

- `crates/core/src/retention/mod.rs` — public surface: `RetentionPolicy`,
  `RetentionRule`, `Criteria`, `Decision`, `evaluate`, `apply`.
- `crates/core/src/retention/model.rs` — serde types for the jsonb policy +

- `crates/core/src/retention/apply.rs` — turns `Decision`s into DB mutations by
  calling the Slice 1 `delete_component` / unlist / proxy-cached-delete paths
  (each already does refcount + outbox in one tx) and writes `retention_audit`.
- `crates/core/src/retention/worker.rs` — `RetentionWorker`: claim → load policy
  → fetch candidates → evaluate → apply → record run summary → invalidate cache.
- `crates/db/src/retention.rs` — sqlx queries: claim-next-due repo
  (`FOR UPDATE SKIP LOCKED`), load candidate components/assets with download

  read/write `retention_policy`.
- `crates/server/src/admin/retention.rs` — admin REST handlers + router.
- `crates/server/src/workers.rs` (existing Slice 1 wiring) — register
  `RetentionWorker` alongside the outbox/reconciler workers.
- Download-path hook: in `crates/format-nuget` (flat-container nupkg handler) and
  `crates/core` proxy download path — bump `last_downloaded_at` /
  `download_count` (§3.7).

### 3.3 Endpoints (admin REST, admin-only via Slice 1 authz seam)

All require `User` with `is_admin = true` (reuse the existing
admin guard / principal middleware).

| Method | Path | Request | Response |
|---|---|---|---|
| `GET`  | `/admin/repositories/{repo}/retention` | — | `200 {policy: <jsonb|null>, last_run: <retention_run|null>}` |
| `PUT`  | `/admin/repositories/{repo}/retention` | `{policy: <RetentionPolicy>}` | `200 {policy}` / `400` on validation error |
| `DELETE` | `/admin/repositories/{repo}/retention` | — | `204` (clears policy) |
| `POST` | `/admin/repositories/{repo}/retention/preview` | `{}` (optional `{at: <ts>}`) | `200 {decisions: [...], counts: {...}}` — **dry run, no mutation, no outbox** |
| `POST` | `/admin/repositories/{repo}/retention/run` | `{}` | `202 {run_id}` — sets `next_run_at = now()` so the worker claims it promptly (does **not** run inline) |
| `GET`  | `/admin/repositories/{repo}/retention/audit?run_id=&limit=&before=` | — | `200 {items: [<retention_audit>...]}` |

`PUT` validates the policy (`validate_policy`) and invalidates the repo-config
cache key on success.

### 3.4 Integration with outbox + cache + authz

- **Outbox.** `apply.rs` never touches S3. A `hard_delete` calls the Slice 1
  asset/component delete which, in one transaction: deletes the `asset` rows,
  `UPDATE blob SET ref_count = ref_count - 1`, and — iff a blob hits
  `ref_count = 0` — inserts a `blob_outbox` `delete_object` row with
  `available_at = now + grace`. The existing outbox worker drains it, re-checks
  `ref_count = 0` (revival guard), and deletes the S3 object. Shared blobs
  (`ref_count > 1`) never get an outbox row. The audit row records
  `ref_count_after` and `blob_delete_enqueued` for observability.
- **Cache.** After a run mutates a repo, the worker calls
  `cache.invalidate(repo_config_key)` plus the repo's
  registration/flat/search/service-index document keys (same keys Slice 1
  push/unlist invalidate), so the optional Redis backplane drops stale L1 entries
  cluster-wide. With no Redis, Slice 1's short L1 TTLs bound staleness.
- **Authz.** All policy + run + preview + audit endpoints go through the Slice 1
  admin guard (`is_admin`). The worker itself runs as the system principal and is
  not request-scoped. Read-path download tracking is unaffected by authz.

### 3.5 Scale-out preservation (no in-memory-only state)

- Authoritative scheduling state lives in `retention_run` (Postgres). A cold
  instance reconstructs everything from it. The worker holds nothing in memory
  beyond the row it has currently leased.
- **Claiming a repo** uses `FOR UPDATE SKIP LOCKED` over due `retention_run` rows
  (mirrors the Slice 1 outbox worker), then sets `state='running'`,
  `locked_until = now + lease`, `started_at = now`. Other instances skip the
  locked row, so a repository is evaluated by **at most one instance at a time**.
- The worker runs on **every** instance (like the outbox worker); coordination,
  not leader election, prevents duplication — consistent with §13's
  "no leader election beyond Postgres-lock coordination."
- `locked_until` is a crash-safe lease: if an instance dies mid-run, the lease
  expires and another instance reclaims the repo (re-evaluation is idempotent —
  §3.6 / §6).
- The S3 side effects flow through the outbox, which is already exactly-once
  cluster-wide via `SKIP LOCKED` + revival re-check. This slice adds **no new S3
  path** and thus inherits that safety.

### 3.6 Evaluation algorithm (detail)

Per claimed repository:

1. Load `retention_policy`; if `null` or `enabled=false`, record a no-op run and
   release. If `dry_run_only=true`, proceed but force every decision's
   `dry_run=true` and **skip apply** (audit only).
2. **Snapshot candidates inside a `REPEATABLE READ` transaction** (or read all in
   one query) — for hosted: every `component` of the repo with its primary
   `.nupkg` asset's `blob_sha256`, `created_at`, `component.last_downloaded_at`,
   `listed`, and the version (normalized). For proxy `scope: proxy_cached` rules:
   every `proxy_cached_version` with `first_seen_at`, `last_downloaded_at`,
   `downloaded`. A consistent snapshot makes protection counts (`keep_last_n`)
   well-defined.
3. **Group by `package_name`.** For each group, sort versions by NuGet semver
   **descending** (newest first).
4. **Compute protections per group** (a protected version is *never* deleted):
   - `keep_last_n` → the first N versions in the semver-desc order.
   - `keep_n_most_downloaded` → the N versions with the most recent
     `last_downloaded_at` (nulls last).
   Protection is the **union** across all rules' protections for that group.
5. **For each version, evaluate every applicable rule** (rule applies if
   `release_type` and `package_name_prefix` match). A rule *selects* the version
   iff all of its present criteria are satisfied (AND):
   - `older_than_days`: `now - created_at >= days`.
   - `not_downloaded_for_days`: `last_downloaded_at` is null **or**
     `now - last_downloaded_at >= days`. (A never-downloaded old component is a
     prime eviction target — matches Nexus treating "never downloaded" as
     eligible.)
   - (`keep_last_n` / `keep_n_most_downloaded` inside a rule are protections, not
     selectors — handled in step 4.)
6. **Apply protection override:** a version selected by any rule but protected by
   step 4 yields **no decision**. Otherwise the highest-severity action wins:
   `hard_delete` > `unlist`. (If a rule says unlist and another says delete, we
   delete.)
7. Emit `Decision { target, action, rule_id, reason }`. `reason` captures matched
   criteria + whether a protection was considered, for the audit row.
8. **Proxy rules** (`scope: proxy_cached`): for each `proxy_cached_version`,
   `not_pulled_for_days` matches when `last_downloaded_at` (or `first_seen_at`
   if never pulled) is older than the threshold. Decision deletes the cached
   version (and its asset/blob if `downloaded=true`), driving the outbox.
   Proxy cached entries are never "unlisted" — eviction = delete; they re-cache
   on the next pull.
9. **Apply** (skipped for dry-run): iterate decisions, each in its **own small
   transaction** via the Slice 1 delete/unlist path, then insert the
   `retention_audit` row in the *same* transaction (so audit and effect commit
   atomically). Batched (e.g. 100 decisions/tx-group with per-decision tx) to
   bound lock duration and let concurrent pushes interleave.
10. Record `last_run_summary`, set `state='idle'`,
    `next_run_at = now + max(min_run_interval, global_interval)`,
    `finished_at = now`, clear `locked_until`. Invalidate cache (§3.4).

The evaluator (steps 3–8) is a **pure function** of `(repo_kind, now, policy,
candidates)` → `Vec<Decision>`, making it fully unit-testable without a DB.

### 3.7 Download tracking

- **Hosted/group download** (flat-container nupkg GET in `format-nuget`): after
  successfully streaming the blob, fire a best-effort
  `UPDATE asset SET last_downloaded_at = now(), download_count = download_count + 1
   WHERE id = $1` and `UPDATE component SET last_downloaded_at = now() WHERE id =
   $2`. Done off the response hot path (spawned task / fire-and-forget), failures
   logged not propagated — same posture as Slice 1's `token.last_used_at`.
- **Proxy download:** when a `proxy_cached_version` transitions to
  `downloaded=true` and on every subsequent cache hit, set
  `last_downloaded_at = now()`.
- These are **not** authoritative for correctness — only inputs to retention — so
  best-effort writes are acceptable and don't violate the no-in-memory-only-state
  rule (the data is in Postgres; we just tolerate occasional lost increments).

### 3.8 Concurrency / race analysis with pushes

- **Push during evaluation.** Evaluation reads a snapshot; a push that lands
  after the snapshot is simply considered next run. A push of a version the
  evaluator decided to delete: the delete runs in its own tx using the Slice 1
  delete path. If a redeploy/push **revived** the same `(repo, name, version)` or
  re-incremented the blob, the **outbox revival re-check** (§4) prevents S3
  deletion of a now-referenced blob. For component-level: deletion targets a
  specific `component.id`; a re-push creates a new component row (unique
  `(repository_id, name, version)` — after our delete commits) or, with
  `allow_redeploy`, takes `SELECT … FOR UPDATE` on the component. We mitigate the
  delete-vs-redeploy race by having `apply` re-verify the component still matches
  the decision (same `id`, still meets the age criterion) inside the delete tx
  via `SELECT … FOR UPDATE`; if the row changed, skip and audit as `skipped`.
- **Two instances, same repo.** Prevented by `FOR UPDATE SKIP LOCKED` on
  `retention_run` — only one holds the lease.
- **keep_last_n vs. concurrent push.** If a new newest version is pushed during a
  run, our snapshot's "newest N" is stale, but the only risk is deleting a
  version that *would* have been protected by the newcomer pushing it out of the
  top N — which is the correct end state anyway (it's no longer in the top N).
  No protected version is ever wrongly deleted because protection is computed
  from the snapshot and re-verified at apply time.
- **Shared blob across repos.** Deletion only decrements `ref_count`; the outbox
  enqueues a delete **iff** `ref_count` reaches 0, and the worker re-checks 0 at
  drain time. A blob referenced by another repo's asset is never deleted.
- **Crash mid-run.** Lease (`locked_until`) expires → reclaimed; already-committed
  per-decision txs (effect + audit) are durable and not redone (the component is
  gone, so it isn't a candidate next time). Partial progress is safe and
  idempotent.

## 4. Phased implementation plan (TDD: test first)

> File paths use the Slice 1 crate layout. Each phase lands behind tests.

### Phase 0 — Migrations & schema

1. `migrations/00NN_retention_schema.sql` — the `ALTER TABLE`s + `retention_run`
   + `retention_audit` from §3.1.
   - **Test:** `crates/db/tests/migrations.rs` (extend Slice 1's migration test):
     apply migrations against a testcontainers Postgres, assert columns/tables
     exist and `retention_policy` accepts/rejects jsonb shapes.

### Phase 1 — Policy model + validation (pure)

2. `crates/core/src/retention/model.rs` — serde `RetentionPolicy`,
   `RetentionRule`, `Criteria`, `Action`, `ReleaseType`, `Scope`;
   `validate_policy(&RetentionPolicy, repo_kind) -> Result<(), PolicyError>`.
   - **Test (first):** `crates/core/src/retention/model.rs#[cfg(test)]` — round-trip
     serde of the §2 example; reject proxy_cached scope on hosted; reject negative
     counts / empty rules / unknown action; accept minimal valid policy.

### Phase 2 — Pure evaluator

3. `crates/core/src/retention/evaluate.rs` — `CandidateComponent`,
   `ProxyCandidate`, `Decision`, `evaluate(...)`, `evaluate_proxy(...)` per §3.6.
   Pull in a semver compare helper (reuse Slice 1 version normalization from
   `format-nuget`/`core`; if it lives in `format-nuget`, expose a comparison fn
   in `core` or accept a pre-sorted order key — **assumption flag:** Slice 1
   version ordering utility location).
   - **Tests (first), table-driven:**
     - keep_last_n protects newest N; older ones with `older_than_days` deleted.
     - `not_downloaded_for_days`: never-downloaded matches; recently-downloaded
       protected.
     - `keep_n_most_downloaded` protects by recency of `last_downloaded_at`.
     - release vs prerelease filtering (`release_type`).
     - `package_name_prefix` filtering.
     - protection-overrides-selection (a version selected by an age rule but in
       top-N is **not** deleted).
     - hard_delete beats unlist when both rules match.
     - proxy `not_pulled_for_days` using `last_downloaded_at` else `first_seen_at`.
     - empty policy / disabled ⇒ no decisions.

### Phase 3 — DB access layer

4. `crates/db/src/retention.rs` — queries:
   - `claim_next_due_repo(now, lease) -> Option<RepoRun>` (`SELECT … FROM
     retention_run JOIN repository … WHERE state='idle' AND next_run_at<=now
     AND repository.retention_policy IS NOT NULL FOR UPDATE OF retention_run
     SKIP LOCKED LIMIT 1`, then mark running + lease).
   - `load_candidate_components(repo_id)` / `load_proxy_candidates(repo_id)`.
   - `upsert_retention_run(repo_id)`, `finish_run(repo_id, summary, next_run_at)`,
     `release_stale_leases(now)`.
   - `insert_audit(rows)`, `read_policy`, `write_policy`.
   - **Tests (first):** `crates/db/tests/retention.rs` (testcontainers Postgres):
     seed two repos with policies; assert `claim_next_due_repo` returns one and a
     second concurrent call (separate tx) returns a *different* repo / `None`
     (SKIP LOCKED dedupe); assert stale-lease reclaim.

### Phase 4 — Apply path (outbox integration)

5. `crates/core/src/retention/apply.rs` — `apply(decisions, deps) -> RunSummary`:
   per decision, open tx, `SELECT … FOR UPDATE` the component, re-verify it still
   matches, call Slice 1 `delete_component`/unlist (which does refcount + outbox)
   or proxy-cached delete, insert `retention_audit` in the same tx; on dry-run,
   skip mutation and write `dry_run=true` audit (or return without persisting,

### E2E (Slice 1 harness, in-process server)

   `keep_last_n=10` + `older_than_days=0`; run worker; assert 5 oldest

   the Slice 1 outbox worker, S3 objects for the 5 deleted blobs gone (HEAD 404),
   audit has 5 rows.
2. **keep-for-X-days + not-downloaded:** push versions with backdated
   `created_at`; download some; policy `older_than_days=30` +
   `not_downloaded_for_days=30`; assert only old **and** cold versions deleted,
   recently-downloaded ones retained.
3. **unlist action:** policy `action=unlist`; deleted-by-policy version hidden
   from search but still downloadable by exact version (Slice 1 unlist semantics),
   no blob deleted.
4. **shared blob not deleted while referenced:** push identical bytes to repo A
   and repo B (one blob, `ref_count=2`); retention deletes the version in repo A;
   assert `ref_count=1`, **no** `blob_outbox` row, S3 object still present;
   retention/admin-delete the version in repo B; assert outbox worker removes the
   S3 object and `blob` row.
5. **proxy evict-not-pulled:** seed `proxy_cached_version` rows with old
   `first_seen_at`/`last_downloaded_at`; policy `proxy-evict-cold`
   `not_pulled_for_days=30`; assert cold cached versions evicted (rows gone,
   downloaded blob refcount decremented + outbox enqueued) and a recently-pulled
   one retained.
6. **multi-instance dedupe of evaluation work:** start two in-process server
   instances against the same Postgres + versitygw; arm a policy on a repo; assert
   the repo is evaluated by exactly one instance per cycle (audit rows attributable
   to a single `run_id`; no double-deletes; counts consistent) — directly mirrors
   Slice 1's scale-out e2e for the outbox.
7. **race with concurrent push:** while a run is in progress (inject a small
   delay between snapshot and apply via a test hook), push a new newest version;
   assert no protected/just-pushed version is deleted and the run completes
   consistently.
8. **dry-run preview:** `POST …/preview` returns the same decision set the worker
   would apply, with **zero** DB mutation and **zero** outbox rows.
9. **crash mid-run reclaim:** simulate lease holder dropping (set `locked_until`
   in the past, `state='running'`); next worker tick reclaims and completes;
   already-applied decisions are not redone.

## 6. Security & failure modes (slice-specific)

- **Never delete a still-referenced blob.** Guaranteed two ways: (a) apply only
  decrements `ref_count` and conditionally enqueues an outbox row when it reaches
  0; (b) the Slice 1 outbox worker re-checks `ref_count = 0` at drain time
  (revival guard). This slice adds no direct S3 delete, so it cannot bypass these.
- **Crash mid-evaluation.** Per-decision txs commit effect+audit atomically; the
  lease expires and another instance reclaims; re-evaluation is idempotent
  (deleted components are no longer candidates; protections recomputed). No
  duplicate S3 deletes (outbox is exactly-once cluster-wide).
- **Runaway/misconfigured policy mass-deletion.** Mitigations: `validate_policy`
  rejects degenerate rules; `dry_run_only` flag lets operators stage; `preview`
  endpoint; full `retention_audit`; `apply_batch_size` bounds blast radius per
  cycle; an optional safety cap (config `retention.max_deletes_per_run`) aborts a
  run that would exceed it and records `last_error`. (Open question whether cap
  is on by default.)
- **Authz.** Only admins configure policies, trigger runs, preview, or read
  audit — through the Slice 1 admin guard. The worker runs as a system principal,
  not user-influenced.
- **Download-tracking spoofing / DoS.** `last_downloaded_at` is best-effort and
  non-authoritative; worst case a flood of downloads keeps a package alive
  (matches Nexus's last-downloaded semantics) — acceptable and not a security
  boundary.
- **Audit integrity.** `retention_audit` is append-only; `component_id` FK is
  `ON DELETE SET NULL` so audit survives the component's hard delete.
- **Time source.** Use Postgres `now()` for all comparisons (single clock) to
  avoid instance clock skew affecting age criteria across the cluster.

## 7. Open questions / risks

1. **Scheduling granularity.** Fixed interval + per-repo `min_run_interval` +
   manual trigger vs. cron expressions per policy. Cron deferred; is per-repo
   interval enough for v1?
2. **Selectors.** Only `package_name_prefix` now; Nexus supports full
   name/namespace/path regex. Full content selectors overlap with §12.4 RBAC —
   keep minimal here, or add a regex selector now?
3. **`keep_n_most_downloaded` tie-breaking** when `last_downloaded_at` is null for
   many versions — fall back to `created_at`? (Proposed: nulls last, then
   semver-desc as tiebreaker; confirm.)
4. **Group repos.** A group has no components of its own (it resolves members);
   retention on a group should be rejected at config time (only hosted/proxy).
   Confirm and enforce in `validate_policy`.
5. **Default safety cap** (`max_deletes_per_run`) on or off by default, and its
   value.
6. **Audit retention.** `retention_audit` grows unbounded; do we need a retention
   policy for the retention audit (meta), or a periodic prune by age?
7. **Version-ordering utility location** (assumption flag): the evaluator needs
   Slice 1's NuGet semver normalization/compare; confirm it's exposed where
   `core` can call it.

## Cross-slice notes

- **Reuses, does not fork, Slice 1 blob GC:** all S3 deletion flows through the
  existing `blob_outbox` + outbox worker + orphan reconciler. The spec's §4 note
  ("retention reuses this exact machinery") is honored literally.
- **Adds columns to Slice 1 tables** (`asset`, `component`,
  `proxy_cached_version`, `repository`) — Slice 1 migrations must land first.
- **Touches the §12.6 frontend later** (policy editor + download stats UI consume
  these endpoints + `download_count`).
- **Selector scope intentionally minimal** to avoid colliding with §12.4 RBAC
  content selectors.
