`PATCH /admin/users/{id}` applied a service account's `description` and
`realm` in one transaction and `active` in another: `{"active": false,
"realm": "lb"}` left the account active in its new realm for a moment, and
a failure in the second step left the first applied. All of a request's
fields are now applied in one transaction, or none. The service account
page sent the realm with every save, so once the realm had been renamed or
deleted since the page loaded, saving a new description alone failed with
400; it now sends only what was changed. A description is also refused
when it holds an invisible formatting character, such as a right-to-left
override (U+202E) that made it read otherwise in the admin list than it
is; zero-width joiners, which emoji and some scripts need, stay allowed.
