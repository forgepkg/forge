Proxy repositories keep the upstream documents they read (npm packuments,
NuGet registrations, version listings and service indexes) for every
instance and across restarts: the bytes in the object store, like packages,
and in PostgreSQL when the upstream last sent or confirmed each and its
`ETag` / `Last-Modified`. Within the metadata TTL any instance serves the
stored copy without asking the upstream; after it, the proxy asks whether
the document changed (`If-None-Match`, `If-Modified-Since`) and a
`304 Not Modified` downloads nothing. Before, each instance fetched every
document itself, a restart forgot them all, and large packuments evicted
each other from the in-process cache long before their TTL ended. The new
`forge.proxy.upstream.documents` metric counts the documents served stored,
revalidated or downloaded. Invalidating a proxy's cache, repointing it or
deleting it deletes its stored documents; ones no request read for a week
are removed.
