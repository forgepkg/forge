An apt proxy kept every pool file and `by-hash` copy for good, never
re-validated, even when it could not check it: a package no `Packages` index
lists (Ubuntu's `_all` packages), one cached while the index could not be
fetched, and `MD5Sum`, `SHA1` and `SHA512` `by-hash` copies, of which only
`SHA256` ones were checked. A wrong copy, from an on-path attacker on a plain
`http://` upstream or a package re-uploaded under its path, then gave every
client "Hash Sum mismatch" until the proxy was recreated. A file is now kept
for good only once its size and digest were checked (a `by-hash` copy against
the digest its path names, for every hash type), and re-validated after the
metadata TTL otherwise. **Invalidate cache** has the files kept for good
fetched again and checked anew, and an administrator can evict one with
**Delete cached file** on the repository's page
(`DELETE /admin/repositories/{name}/files?path=<path>`).
