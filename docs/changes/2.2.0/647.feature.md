Whether a client may sign in with a password over HTTP Basic (a NuGet, raw
or Helm feed, `docker login`, `npm login --auth-type=legacy`) is set per
realm: **Accept passwords from clients (HTTP Basic)** on the local and
credential-forwarding realms under **Admin → Authentication**
(`accept_client_passwords`). A credential-forwarding realm accepts its
users' passwords by default, as a Nexus that checks them does; the local
realm accepts none by default, and its users sign their clients in with
tokens. An enabled credential-forwarding realm no longer opens the local
realm's passwords to every client as well, and a password a client sends
for a local account while the local realm is closed is refused like a wrong
one and never forwarded upstream. The browser login takes every realm's
passwords, and an API token works as before.
