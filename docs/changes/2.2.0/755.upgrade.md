`POST /admin/users` with an explicit `"role": "reader"` now gives the new
account the built-in `reader` role, read on every repository, private ones
included. In 2.1 `reader` meant no built-in role, and the service-account
form and API examples sent it: a provisioning script or Terraform module
written for 2.1 that creates a service account with `"kind": "service"` and
`"role": "reader"` succeeds as before, and the account now reads every
repository instead of only what its own roles grant. The service accounts
that exist at the upgrade are not widened, only the ones created after it.
Change such requests to send `"role": "roles_only"`, or to leave `role` out,
which means the same for a service account. Make the change together with
the upgrade: 2.1 does not accept `roles_only`. `PATCH /admin/users/{id}`
takes no `role`, so it is not affected.
