Ten wrong device login codes from one network, typed by one user or
looked up by a malicious page opening `/device?code=…` for a signed-in
victim, locked every user of that network (and, without
`auth.trusted_proxy_cidrs`, every user of the install) out of the `/device`
page for five minutes. A network may now enter a hundred wrong codes per
five minutes, a session still ten, and a code filled in from the client's
link is looked up only once the user clicks **Continue**.
