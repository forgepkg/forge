Deleting a manifest or a whole image (from the web UI's image page, with
`DELETE /admin/repositories/{name}/images`, or by image retention) while a
push moved a tag of the same image, or while a tag of it was deleted, could
deadlock: the delete locked the image's manifests and then its tags, the
tag's writer the tag and then its manifest, and whichever Postgres aborted
answered 500 (a retention run failed its batch). Every write to an image's
manifests and tags now takes one lock on the image first, so they wait for
each other instead.
