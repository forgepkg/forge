The image list of a docker group in the web UI (`GET /browse/images` of a
group, run again on every keystroke of a search) read each member's images
in `OFFSET` pages of 1,000, each grouping every image before it again, so
its database work grew with the square of a large proxy's images, and it
also read every image of the group's owning hosted members. Members are now
read a batch at a time by name, each batch costing only its own images,
and whether an owner holds an image is asked only of the images a member
that is no owner would list. A hosted or proxy repository listed to a
caller with a content selector is read the same way.
