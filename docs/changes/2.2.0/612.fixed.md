Deleting a whole image from the web UI (or `DELETE
/admin/repositories/<name>/images` without a `reference`) locked every
manifest and tag of the image and deleted the manifests one by one in a
single transaction, about three statements each. For an image of tens of
thousands of manifests, pulls waited on those locks, each holding a database
connection, and a delete that ran past `server.request_timeout_seconds` was
rolled back, so such an image could not be deleted at all. The image is now
deleted 100 manifests at a time, the newest first, each batch in a
transaction of its own with a few statements whatever its size. Deleting one
manifest with what only it kept takes a few statements too.
