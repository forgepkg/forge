A group member can be scoped to package ids: `"packages": ["@fortawesome/*"]`
when adding it to a group, or `PATCH /admin/repositories/<group>/members/<member>`
later, and the group asks it only about the ids those patterns match (globs,
a content selector's syntax, matched case-insensitively; empty, the default,
is every id). For any other id the member is not asked at all: no upstream
request, no cached not-found. A proxy that passes a public registry through
(GitLab's npm registry, npm.fontawesome.com, a Nexus proxying nuget.org) is
then no longer asked about every public package the group serves. Scopes hold
for search and for nested groups, apply to npm, NuGet and Docker / OCI groups
(groups of files have none), and only narrow: prefer hosted, reserved prefixes
and owners are decided as without them. The group's **Members** screen sets a
scope when adding a member and changes it with **Packages** on its row
([npm](docs/npm.md#scoping-a-member-to-its-packages)).
