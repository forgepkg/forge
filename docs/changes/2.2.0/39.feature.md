Once a token is created under **Your tokens** (or on an account's page under
**Admin → Users** and **Admin → Service accounts**), the page shows how to
use it, with the token and the account's username filled in, for a
repository it reaches: `docker login` and `helm registry login`, `npm config
set` with the `.npmrc` and `.yarnrc.yml` lines, `dotnet nuget add source`,
`dotnet nuget push` and a `NuGet.config`, `curl` with the token as the
password or as a Bearer token, and apt's `auth.conf.d` entry. The tokens a
user creates or revokes in the web UI, and the sign-ins of the web UI
(password and OIDC, also those refused), are audit-logged (`forge::audit`),
like the client logins already were. A new page,
[docs/nuget.md](docs/nuget.md), connects NuGet clients, and
[docs/raw.md](docs/raw.md#logging-in) says how curl and other HTTP clients
log in.
