The page of an image in the web UI (`GET /browse/images/{repo}/{image}`)
lists at most its newest 1,000 tags and 1,000 manifests, but every request
still read all of the image's manifests and tags from the database, with
the tags and the children of each, before it kept those: work that grew
with the image, for any reader of the repository, once per member of a
group. The page now reads the manifests it lists, through a new index on
`oci_manifest` (repository, image, push time) that the upgrade's migration
builds, and counts the others. What it shows is unchanged.
