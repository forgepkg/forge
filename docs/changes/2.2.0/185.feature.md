Retention policies run on a cron schedule in a time zone (`schedule`,
`schedule_timezone`: `0 3 * * *` in `Europe/Berlin` runs at 03:00 Berlin
time, summer and winter), as an alternative to `min_run_interval_seconds`,
and `max_run_seconds` stops a run at the end of its window, the next run
going on with the rest; Run now still runs at once, and the Retention
screen shows the schedule, the next run and a draft's next run times. This
holds for package, raw file and image policies. Package rules gain the
triggers `prerelease_superseded_for_days` (a prerelease once a release that
comes after it has been out N days), `unlisted_for_days` (delete what was
unlisted N days ago) and `max_versions_per_package` (a pure count, on proxy
rules too), and the filters `version_pattern` / `exclude_version_pattern`
(globs on the version), `selector` (a content selector, which cannot be
deleted while a rule names it) and `release_type: snapshots`; image rules
gain `tag_pattern` / `exclude_tag_pattern` and globs in `protected_tags`.
Protections win over every trigger, the preview shows each decision's
reason, and the Retention screen edits every field. The format contract
gets retention hooks (`version_class`, `retention_partition`) so a format
says what a prerelease, a snapshot and "the newest N" are; `docs/retention.md`
lists every rule with examples.
