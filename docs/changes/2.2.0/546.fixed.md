The web UI's confirmation of an image delete counted the rows the image page
lists, at most the newest 1,000 tags and 1,000 manifests: an image of 50,000
tags was announced as "1,000 tags and 1,000 manifests", a manifest's delete
could leave out tags and referrers it takes and the warning that an index
lists the manifest, and deleting a chart version did not say that the other
tags of its manifest (`oras tag`, `crane tag`) go too. The whole image is now
counted by its totals, and a manifest's or chart version's confirmation shows
what the server would delete: every tag on the manifest, the manifests and
referrers that go along, and the indexes that list it. The admin API answers
that as `GET /admin/repositories/<name>/images/delete-preview`, with the
delete's `image` and `reference`.
