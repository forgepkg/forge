An npm tarball's header blocks did not count toward `npm.max_unpacked_bytes`,
so a tarball of very many empty entries, which inflates about a thousandfold,
was bounded by the upload's size alone. The header blocks now have the same
bound again, apart from the files' data: a package whose files fit the bound
is accepted as before. `dist.unpackedSize` also counted what npm does not,
the data of PAX headers and GNU long names and entries of types npm skips;
it is now the size `npm pack` reports. Versions already published keep the
value they were stored with.
