With `[telemetry]` on, the OpenTelemetry SDK's warnings about an `OTEL_*`
value it cannot use were lost, because it reads them before the log is set
up: a `telemetry.samplerArg: "10%"` in the Helm values, or any
`OTEL_TRACES_SAMPLER_ARG` that is no number, silently sampled every trace.
The warnings are now printed on the console. A start that fails (the
database, the migrations, the bucket) was only printed to stderr and the
telemetry was not flushed, so with `telemetry.logs` the log backend never
showed why an instance was crash-looping; the failure is now logged as an
error, `forge-server failed to start`, and exported before the process ends.
