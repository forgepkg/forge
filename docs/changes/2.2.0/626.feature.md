Workload identity: a rule of a self-managed issuer can take every project of
the issuer (`"issuer_wide": true`, **Every project of this issuer** in the
realm's rules), so every CI job of a self-managed GitLab can restore without
a list of namespace or project IDs to keep current. Such a rule needs no
identity condition (conditions such as `ref_protected` may narrow it), must
come after every other rule, and is refused for GitHub Actions and
GitLab.com. A job it matched holds its role's grants capped at `read`, with
the CI token, an exchanged key and registry tokens alike; a rule for a
project ahead of it, or a trusted publisher, still lets a project publish.
Realms without such a rule keep their keys on upgrade.
