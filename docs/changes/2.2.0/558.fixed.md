With an outbound proxy set for the proxy repositories (`HTTPS_PROXY`,
`HTTP_PROXY` or `ALL_PROXY`) and no `NO_PROXY` entry for the Collector, the
telemetry export went to that proxy, also for the default
`http://localhost:4318`: the exports failed, and to a plain-HTTP endpoint the
proxy was sent the telemetry and `OTEL_EXPORTER_OTLP_HEADERS` (a vendor's API
key, say) in the clear. Forge now connects to the OTLP endpoint directly,
whatever the proxy variables say. An installation that reached its telemetry
backend through the outbound proxy exports to a Collector instead, which
forwards through the proxy.
