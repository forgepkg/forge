A NuGet package whose `.nuspec` is in UTF-16 with a byte-order mark, as
older packages on nuget.org hold it (`Microsoft.Web.Infrastructure` 1.0.0),
was refused as a malformed manifest, on push and through a proxy of
nuget.org. The manifest is decoded the way NuGet reads it (UTF-16 LE or BE,
or UTF-8 with a byte-order mark), and every other check still applies.
