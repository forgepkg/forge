Forge can be reached under further host names, such as the old Nexus host
pointed at Forge, with URLs rendered for that host: `server.alias_base_urls`
lists them (`["https://nexus.example.com"]`). A request whose `Host` names an
alias gets the client protocols' URLs on it: a NuGet service index lists its
resources there, an npm packument its tarballs, and the registry names
`https://<alias>/v2/token` as its token realm and the alias as its service,
so a client configured with the alias (`dotnet restore`, `docker login`,
`helm pull`) never needs the public host. Any other `Host` keeps URLs on `public_base_url`. The
web UI, sign-in, cookies and connect snippets stay on `public_base_url`, and
a web UI page requested on an alias is redirected there. An alias counts as
one of the server's own names for the trusted-header realms, and no docker
repository may have it as its host (the admin API refuses one, startup fails
while one does). **Admin → System** shows the public URL and the aliases.
See [docs/deployment.md](docs/deployment.md#further-host-names-aliases).
