A local realm that accepts no passwords from clients counted each password
a client still sent for one of its accounts (HTTP Basic on the feeds and
`/v2/token`, `npm login --auth-type=legacy`) as a failed sign-in. A NuGet or
docker client configured with the password before the upgrade therefore
locked its owner out of the browser login (429) from the same network, the
sign-in that gets them a token. Such a password is still refused like a
wrong one, but no longer counts towards the lockout: nothing is checked on
that path. Wrong passwords for realms that check them count as before.
