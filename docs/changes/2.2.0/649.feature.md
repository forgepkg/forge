Command-line clients sign in through the browser with the OAuth 2.0 device
authorization grant (RFC 8628), the login Forge's coming helpers (`forge
login`, `docker-credential-forge`, `nuget-plugin-forge`) use, OIDC and Entra
sign-ins included: `POST /auth/device/code` gives the client a code, which
its user enters on the web UI's new `/device` page (or arrives with it filled
in), checks the client, scope, address and time shown there, and approves;
the client polls `POST /auth/device/token` and receives an API token of that
user, once. `GET /.well-known/oauth-authorization-server` names both
endpoints. Only the helpers' client ids are accepted, a `scope` (`read`,
`write`, `delete`, `repository:<name>`) narrows the token, and no refresh
token is issued: the token lasts `cli_login.token_lifetime_days`, like npm's
browser login's, and is listed and revocable on the user's tokens page.
Wrong codes are limited per network and per session. **Admin → Settings →
Device login** turns it off and sets the polling interval. See
[docs/deployment.md](docs/deployment.md#device-login).
