A workload-identity rule that named a role an administrator had named
`reader` names it under its new name, `reader-<id>`, too, so the CI jobs it
matches keep that role's grants instead of the built-in `reader`'s (every
repository). The keys those realms' jobs exchanged before the upgrade stop
working with the change; the jobs exchange their ID tokens again. A rule
that names `reader` while no role of that name exists, for example because
the role was deleted, refused the jobs it matched until now; from the
upgrade on it grants the built-in `reader`, every repository. Before
upgrading, check the rules of each workload-identity realm under **Admin →
Authentication**, and point such a rule at a role that exists or remove it.
