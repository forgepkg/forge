Two of the upgrade's migrations reach the 2.1 instances that still serve
during a rolling restart; upgrade in a quiet window. The migration that
adds `component.unlisted_at` locks `component` (`ACCESS EXCLUSIVE`) and,
before it commits, writes the column on every unlisted version: until then
every query on `component` waits, from every instance, the 2.1 ones
included. It is brief on most installs and takes longest where many
versions are unlisted, as on a NuGet repository, where a client's delete
unlists (`SELECT count(*) FROM component WHERE NOT listed` counts the rows
it writes). The rename of `nexus_import` to `repository_import` takes the
table away from the 2.1 instances: until the last one is replaced, its
import worker logs `relation "nexus_import" does not exist` every few
seconds and its import API fails with the same error, and an import running
on it stops there. Let running imports finish, or cancel them, before the
upgrade, and start none until every instance runs 2.2.0. An import caught
by the upgrade stays `running` and is continued by a 2.2.0 instance once
its lease has run out (two minutes), as a resumed one is.
