An import accepted a source `url` or `registry_url` with credentials in it
(`https://user:pw@apt.example.com/debian`, as `sources.list` may write it),
and the import worked, since the credentials went to the source as Basic
auth. The password was then never sealed nor deleted on completion: it was
stored in plaintext with the import, returned by every view of it and shown
in **Admin → Repositories → Import**, and logged in the import's log lines
and the audit line of every imported package, file and image. Such a URL
is now refused with 400, as a proxy's `remote_url` is; give the
credentials as `username` / `password`. An import that already holds one
keeps it until it is deleted: check `GET /admin/repositories/{name}/imports`
for URLs with credentials in them, delete those imports, and change the
password at the source.
