An apt proxy served a pool file whose path names no package (a file name
that is no `<name>_<version>_<arch>.deb` in a directory that is no package
name) to every reader, whatever their package selector allowed, and an
upstream behind Jetty or Tomcat (Nexus, Artifactory) answered such a path
with a package by dropping its `;` path parameters
(`pool/main/o/openssh;x/openssh-server_…_amd64.deb;x`). Such a pool file is
now only served to a reader every package is visible to, others get 404,
and a pool path with a `;` is not found at all.
