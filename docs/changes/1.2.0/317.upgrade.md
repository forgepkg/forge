**Breaking:** every account is named by a UPN, `local-part@domain`
(`alice@example.com`). The first start renames each account whose name is no
UPN to `<name>@example.com` (an `@` in it becoming `+`, a taken name
`<name>#<id>@example.com`) and logs each rename. Users sign in with the new
name; accounts keep their passwords, roles, tokens and identity links, and
API tokens keep working whatever name a client sends with them, but a
password sent over Basic needs the new name. `POST /admin/users` answers 400
for a name that is no UPN, and an `oidc` realm provisions an account only when
its claim chain (username claim, verified email, `sub`) yields a UPN;
otherwise the login is refused and the login page names the claim. Entra's
`preferred_username` is the UPN; with another IdP, map a claim that holds one.
The rename goes away in 1.3.0: upgrade to 1.3 from a 1.2 release.
