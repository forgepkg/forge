[GitLab CI with workload identity](docs/gitlab-ci.md#every-project-on-a-runner)
shows how a GitLab Runner of your own runs the token exchange once for every
job it builds, so that the projects only ask for the ID token, and how a
runner can carry a service account's read token instead. A job with a
`before_script` of its own keeps the exchange with `!reference`.
