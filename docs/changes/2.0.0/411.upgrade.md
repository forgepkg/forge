A grant gives one of three ordered access levels instead of one verb:
`read` < `write` < `delete`, each including the ones below it, and
administration is only membership in the built-in `admin` role. Migration
0046 does not carry every grant over. The grants a role held on one
repository (or every repository) and content selector become one grant
where their verbs are exactly a level (`read`; `read` and `write`; `read`,
`write` and `delete`), which keeps the built-in roles as they were. Grants
of any other combination (`write` without `read`, `delete` without `write`)
are deleted rather than widened, as is every `admin` grant: review your
custom roles after the upgrade and give them the levels they need. Token
scopes change the same way: `actions` becomes `level` (`read`, `write` or
`delete`), with `"admin": true` for the admin opt-in that `"admin"` in
`actions` gave. A stored scope whose actions are exactly a level is
converted, `{"actions": ["admin"]}` of an administrator becomes
`{"admin": true}`, and every other token whose scope listed actions is
revoked and has to be issued again. The grants API
(`/admin/roles/{id}/grants`), token creation and
`PATCH /admin/tokens/{id}/scope` take and return `level`, and answer 400
naming it to a request that still sends `action` or `actions`;
`/admin/users/{id}/effective` reports levels.
