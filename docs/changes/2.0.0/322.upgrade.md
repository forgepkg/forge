`POST /admin/users` takes no password any more: send `{"username",
"email", "role"}` (`role` is `reader`, `writer` or `admin`, replacing
`is_admin`; `active` is gone too), and the user chooses the password from the
invitation, whose `link` the answer carries when no email went out. A body
with `password`, `is_admin` or `active` is refused. Scripts that create users
with a password accept the invitation instead: `POST
/auth/invitations/accept` with the link's token and the password (at least 12
characters). Accounts of a credential-forwarding realm are created as before,
with `realm`.
