Helm: a version's index entry carried its Chart.yaml metadata whole (up to
1 MiB), and every `index.yaml` request renders every version, so a user who
may push to a Helm repository, even one chart, could push a few hundred
versions with a long description and make every `helm repo update` take
gigabytes of memory until the pod was OOM-killed. A version's summary, and
so its index entry, now takes at most 16 KiB: past that, the description is
cut to 1 KiB, then the largest fields (annotations, maintainers, …) are left
out until it fits, and the fields Helm needs (`apiVersion`, `name`,
`version`, `appVersion`, …) go last. A version pushed before is cut down the
same way when the index is rendered. The host also stores no manifest
summary over 64 KiB from a WebAssembly format plugin.
