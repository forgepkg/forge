**Breaking:** secret encryption at rest is required. `[crypto]` names exactly
one root provider, `env` or `file`; `crypto.enabled` is gone, and Forge
refuses to start without a usable root key, naming what to set:
`FORGE_CRYPTO__ROOT__PROVIDER=env` with `FORGE_ROOT_KEY`, or
`FORGE_CRYPTO__ROOT__PROVIDER=file` with `FORGE_CRYPTO__ROOT__ROOT_KEY_PATH`.
The Helm chart uses the `env` provider and refuses to render without
`FORGE_ROOT_KEY` (in `secretEnv`, `existingSecret` or `env`); the kustomize
base sets the provider and the overlays' `forge.env` holds the key.
`GET /admin/crypto/keys` no longer reports `enabled` or
`plaintext_backfill_pending`, and a rotation no longer answers 409 for
encryption being off.

Generate the root key with `openssl rand -base64 32`, and keep it in your
secret manager and with your backups. Without it, the stored secrets cannot
be read: the proxy passwords, realm secrets and email credentials have to be
entered again, and Forge generates a new registry-token key and new issuer
keys. Packages and metadata are not affected.
