Whether retention runs and how long its audit log is kept are no longer
configured in `forge.toml`: an administrator sets them under **Admin →
Retention** (or `GET`/`PUT /admin/settings/retention`), for every instance at
once. Their keys are removed, and startup refuses a configuration that still
sets one, `FORGE_RETENTION__*` variables included: `retention.enabled`,
`retention.audit_retention_seconds` and `retention.default_run_interval_seconds`.
Their values are not carried over: after the upgrade, retention runs and its
audit rows are kept 90 days. `retention.default_run_interval_seconds` is gone
without a replacement: each policy's own `min_run_interval_seconds` (default
one hour) decides how often it runs, so a policy that asks for less than an
hour now gets it. `retention.poll_interval_seconds` and
`retention.lease_seconds` stay in the configuration.
